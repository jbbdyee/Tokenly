# Tokenly

여러 AI 서비스의 사용량을 통합 표시하려는 SwiftUI 메뉴 막대 앱입니다. 사용자는 Codex와 Google Antigravity(AGY)의 실제 한도 표시 성공을 보고했습니다. 숫자형·최소형·아이콘형 메뉴 막대 표시와 팝오버 열기, 설정 창 네 탭, 스타일·테마 즉시 적용과 재실행 후 복원을 실제 GUI에서 확인했습니다. Claude 구독 한도는 공식 상태줄 수신 코드가 추가됐으나 **사용자 설정 연결과 실제 계정 수신은 아직 완료되지 않았습니다.** OpenAI API 연동은 보류 중이며 Gemini 자동 조회는 지원하지 않습니다. AGY는 Gemini와 별도 서비스입니다.

## 실행

1. macOS 14 이상에서 일반 사용자 터미널의 Codex CLI 설치와 기존 계정 로그인 상태를 확인합니다 (`codex --version`).
2. Xcode 없이 실행하려면 Finder에서 `.app`을 엽니다. 현재 점검 빌드는 `/private/tmp/tokenly-v1-release/Build/Products/Release/Tokenly.app`에 있으며 [dist 앱](dist/Tokenly.app)과 `/Applications` 설치본은 교체하지 않았습니다. 빌드는 로컬 임시 사용을 위한 것이고 배포용 서명·공증은 하지 않았습니다.
3. 개발하려면 [Tokenly.xcodeproj](src/Tokenly.xcodeproj)를 Xcode에서 열고 `Tokenly` 스킴·`My Mac`을 선택해 실행할 수 있습니다.
4. 메뉴 막대에서 기본 숫자형 `5h …% · 7d …%`로 Codex 잔여 비율을 확인합니다. 설정의 `메뉴 막대` 탭에서 최소형(두 비율)·아이콘형(번개와 5시간 비율)으로 바꿀 수 있습니다. 클릭하면 Codex·AGY 요약 행을 각각 접고 펼칠 수 있습니다. 기본값은 Codex 펼침·AGY 접힘이며 선택은 재실행 후에도 유지됩니다. 상단 버튼 하나로 전체 새로고침을 실행하고 앱은 5분마다 자동 갱신합니다. AGY는 서버 조회가 아니라 로컬 상태줄 파일을 다시 읽습니다.

Codex는 공식 app-server의 `account/rateLimits/read`를 읽기 전용으로 호출합니다. AGY는 CLI 상태줄이 로컬에 전달한 쿼터 파일만 읽습니다. 인증정보 파일을 직접 읽거나 저장하지 않습니다. 조회에 실패하면 안내를 표시하고, 이전 성공값이 있으면 시각과 함께 이전 데이터라고 표시합니다. 수치는 현재 응답에서 계산하며 앱에 고정하지 않습니다.

Finder 실행 시 터미널과 `PATH`가 다를 수 있어 앱은 일반적인 Homebrew·사용자 설치 경로에서도 CLI를 찾습니다. 다른 위치에 설치했다면 현재 탐색되지 않을 수 있습니다. 사용자는 `/Applications`에 설치한 앱에서 실제 Codex 사용량 조회 성공을 확인했습니다. 앱은 메뉴 막대 전용으로 구성되어 있으며 팝오버의 `종료`로 끝낼 수 있습니다.

## 로그인 시 자동 실행

메뉴 막대 팝오버 상단의 톱니바퀴 버튼으로 별도 설정 창을 열고 `일반`에서 `로그인 시 자동 실행`을 설정할 수 있도록 구현했습니다. 처음에는 자동 등록하지 않습니다. Xcode 빌드나 임시 빌드 경로에서 실행할 때는 토글이 비활성화되며 Applications 폴더 설치 안내가 나타납니다. 사용자는 설정 창 네 탭의 동작을 확인했습니다. 이전 설치본에서는 macOS 시스템 설정으로 Tokenly를 로그인 항목에 직접 추가한 뒤 앱에 `켜짐 · 다음 로그인부터 실행됩니다.`가 표시되는 것을 확인했습니다. 앱 내부 토글만으로 신규 등록·해제하는 동작과 재로그인 후 자동 실행은 미검증입니다. 최초 상태 조회 실패의 정확한 원인도 확인되지 않았습니다.

## 검증 상태

사용자가 Codex·AGY 실제 한도, 세 메뉴 막대 스타일과 각각의 팝오버 열기, 간결화 팝오버·통합 새로고침 버튼, 설정 네 탭, 스타일·테마 즉시 반영과 재실행 복원을 GUI에서 확인했습니다. 새 Claude 코드의 Debug 테스트 타깃과 Release 앱은 빌드됐습니다. **Claude 구현 전에는 일반 사용자 Xcode에서 XCTest 33개가 실제 실행되어 전부 통과했고 커버리지 54%**였습니다. 이후 팝오버 Provider 순서를 **Codex → Claude → Google Antigravity**로 바꾼 작업에서 Debug·Release 빌드가 성공했고, Claude·순서 테스트를 포함한 **XCTest 38개가 실제 실행되어 전부 통과**했습니다. 새 순서의 GUI 확인은 아직 하지 않았으며 `dist`와 설치 앱은 갱신하지 않았습니다. 작은 화면·오류 문구 잘림, 라이트·다크 대비, 로그인 항목 토글과 재로그인은 별도 확인이 필요합니다.

### Xcode에서 테스트하기

1. [Tokenly.xcodeproj](src/Tokenly.xcodeproj)를 Xcode에서 엽니다.
2. 상단 Scheme을 `Tokenly`, 실행 대상을 `My Mac`으로 선택합니다.
3. `Product > Test` 또는 ⌘U를 실행합니다.
4. Test navigator에서 `TokenlyTests` 전체 결과를 확인합니다. 실패하면 해당 케이스의 이름과 오류 메시지를 기록해 주세요. 작업 샌드박스에서는 앱·테스트 번들 빌드 후 `IDETestProgressNotification` 및 `testmanagerd` 접근이 차단됐으며, 이는 테스트 통과 결과가 아닙니다.

## 하트 게이지 시제품

설정 → `메뉴 막대` → `하트형`을 고르면 **메뉴 막대에만** Codex → Claude → AGY 순서로 젤리 하트가 표시됩니다. 팝오버는 기존 구성을 그대로 유지합니다.

- 하트 안에는 그 서비스 한도 중 가장 낮은 잔여율(`30%`)이, 아래에는 이름이 표시됩니다. 잔여율만큼 아래에서 채워집니다.
- 0%는 빈 하트에 `0%`로 표시합니다.
- 이전에 유효한 값을 받았지만 지금 조회가 실패했거나 오래된 경우에는 회색 하트에 마지막 값을 표시합니다.
- 표시를 끈 서비스, 연결되지 않은 서비스, 유효한 값을 받은 적 없는 서비스는 숨깁니다.
- 하트가 하나도 없으면 작은 하트 윤곽 아이콘이 남습니다.
- AGY 하트는 수신 버킷 중 최저값이며 Gemini 구독 전체 사용량이 아닙니다.

검증 상태:

- **구현·빌드:** 완료. Debug·Release 빌드 성공
- **XCTest:** 45개를 실제 실행해 전부 통과
- **실제 계정 데이터 확인:** 하지 않음
- **사용자 GUI 검증:** 1차 시제품 디자인은 사용자가 확인했습니다. 숫자·이름을 넣은 현재 메뉴 막대 하트와 클릭 동작은 미검증이며, 오프라인 렌더링으로만 확인했습니다.
- `dist`와 `/Applications/Tokenly.app`은 갱신하지 않았습니다. Xcode에서 `Tokenly` 스킴을 실행해 확인하세요.

## 곰돌이형·하트형 메뉴 막대

설정 → `메뉴 막대`에서 `곰돌이형` 또는 `하트형`을 고르면 메뉴 막대에 Codex → Claude → AGY 순서로 아이콘이 표시됩니다.

- 아이콘 안에는 잔여율 숫자만 표시합니다(`%` 없음).
- 서비스 이름은 아이콘 아래 윤곽에 가로로 들어가며, 메뉴 막대가 밝으면 검은색, 어두우면 흰색입니다.
- 곰돌이는 3D 렌더링한 글래스 젤리(귀 1.05배, 강함 외곽선), 하트는 기존 젤리 하트입니다.
- 두 스타일 모두 간격 12pt, 높이 22pt이고, 잔여율만큼 아래에서 채워집니다.
- 회색은 이전 데이터이며, 표시를 끈 서비스와 연결되지 않은 서비스는 숨깁니다.
- 팝오버와 다른 스타일은 바뀌지 않았습니다.

검증 상태:

- **구현·빌드:** 완료. Debug·Release 빌드 성공
- **XCTest:** 53개를 실제 실행해 전부 통과
- **실제 메뉴 막대 표시·실제 계정 값 확인:** 하지 않음 (사용자 확인 필요)
- `dist`와 `/Applications/Tokenly.app`은 갱신하지 않았습니다.

## 범위

Codex 구독 한도는 메뉴 막대의 기존 5시간·7일 수치로 표시합니다. AGY는 CLI 상태줄이 제공한 버킷별 잔여 비율과 초기화 시각을 팝오버에 표시합니다. AGY 버킷이 여러 개일 때 접힌 요약은 전체를 한 수치로 대표하지 않고 `버킷 수 · 최저–최고%`로 표시합니다. `3p-weekly` 같은 내부 ID는 공식 의미가 확인될 때까지 원문을 유지합니다. OpenAI API 토큰·비용 코드는 남아 있지만 연결은 보류 중입니다. 알림과 배포 서명은 후속 작업입니다.

`AI 서비스` 설정에서 Codex·AGY·Claude의 **팝오버 표시**를 선택할 수 있도록 구현했습니다. Codex를 숨겨도 메뉴 막대 수치와 5분 조회는 유지됩니다. AGY는 연결 파일이 있을 때 표시 선택을 켤 수 있고, 숨기면 자동 조회 대상에서 제외됩니다. Claude는 기본 숨김·접힘이며 연결 전 표시를 켜면 설정 필요 상태가 나타납니다. 모든 서비스를 숨기면 안내가 표시됩니다. 메뉴 막대 스타일과 팝오버 펼침 상태는 재실행 후 복원하도록 저장합니다. `테마` 탭에서는 시스템 설정 따르기·라이트·다크 중 하나를 선택해 팝오버와 설정 창에 적용합니다. OpenAI API 연동은 보류 중이며 기존 Provider 코드는 남아 있지만 현재 키 등록·조회·팝오버 표시는 사용하지 않습니다. Gemini는 조사 단계입니다. `메뉴 막대` 탭에 **하트형** 1차 시제품을 추가했습니다(아래 참고). 캐릭터형 표시, 메뉴 막대 Provider 선택, Tokenly 전용 앱 아이콘은 후속 과제입니다.

### Claude 구독 연결 준비 상태

새 Claude 브리지는 [공식 Claude Code 상태줄 JSON](https://code.claude.com/docs/en/statusline)에서 5시간·7일 사용률과 초기화 시각만 골라 `~/Library/Application Support/Tokenly/claude-quota.json`에 저장하도록 구현했습니다. Tokenly는 이 파일을 읽어 잔여율과 마지막 수신 시각을 보여 주며, 팝오버 새로고침과 5분 타이머는 **파일을 다시 읽을 뿐 Claude 서버를 조회하지 않습니다**. 상태줄 설정은 아직 연결하지 않았고 실제 구독 데이터를 수신하지 못했으므로 현재 기능은 실계정 미검증입니다. Anthropic API 토큰·비용은 이 구독 한도와 별개입니다.

사용자가 설정 변경을 승인했지만 작업 샌드박스가 `~/.claude`의 백업 생성부터 거부해 설정과 실제 수신 파일은 변경되지 않았습니다. 일반 macOS 사용자 터미널에서 프로젝트 경로로 이동한 뒤 아래 두 명령을 순서대로 실행할 수 있습니다. 첫 명령은 기존 `statusLine`이 있으면 중단하며, 기존 키를 보존하고 0600 백업을 만든 뒤 현재 설정도 0600으로 강화합니다. **성공 시 출력되는 실제 백업 경로와 복원 명령을 보관하세요.** 두 번째 명령은 인증정보나 전체 상태줄 JSON을 출력하지 않습니다.

```sh
cd <프로젝트 경로>
/usr/bin/python3 scripts/enable_claude_statusline.py
/usr/bin/python3 scripts/check_claude_statusline.py
```

상태줄은 Claude Code가 세션 이벤트에서 JSON을 보내며 구독 한도는 첫 API 응답 뒤에만 올 수 있습니다. 설정 후 기존 Claude Code 세션에서 정상적인 작업 이벤트가 발생한 다음 두 번째 명령으로 수신 시각과 필드 유무를 다시 확인하세요. 결과 파일이 없거나 필드가 없다면 실제 연결 성공으로 간주하지 않습니다. 설정 명령은 이 프로젝트의 브리지 소스 파일을 절대 경로로 가리키므로 프로젝트를 이동하면 다시 설정해야 합니다. 새 Claude XCTest와 GUI 표시는 아직 미검증입니다.

## 추가 서비스 연결 준비

- **OpenAI API:** 연동 보류 중입니다. Keychain·조회 구현은 남아 있지만 현재 설정 창에서 키 작업과 실제 조회를 제공하지 않습니다. 관리자 권한과 API 보고 범위는 [OpenAI 관리자 키 문서](https://platform.openai.com/docs/api-reference/admin-api-keys), [Usage](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/completions), [Costs](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/costs)를 참고하세요.
- **AGY CLI:** 이전 작업 환경에서는 설정 백업 생성이 차단됐으나, 이후 사용자가 실제 한도 표시 성공을 보고했습니다. 앱은 AGY CLI가 상태줄 이벤트를 보낼 때 `~/Library/Application Support/Tokenly/agy-quota.json`에 추출된 쿼터를 읽습니다. 15분 넘게 갱신이 없으면 오래된 데이터로 표시합니다. 상태줄 명령을 바꾸거나 인증을 수정하는 작업은 이번 UI 개선에 포함되지 않습니다. [AGY 공식 상태줄 계약](https://antigravity.google/docs/cli/statusline).

AGY 설정과 브리지가 유지되어도 CLI가 새 상태줄 이벤트를 보내지 않으면 파일의 수신 시각은 갱신되지 않습니다. 팝오버의 수동 및 5분 자동 새로고침은 로컬 수신 파일을 다시 읽을 뿐 AGY 서버에 최신 쿼터를 요청하지 않습니다. 수신 후 15분이 지나면 오류로 처리합니다. 같은 앱 실행 중 정상 값이 있었다면 `이전 데이터`와 성공 시각을 붙이고, 재실행 후 이전 값이 없으면 `최신 데이터 없음 · 상태줄 갱신 대기`로 안내합니다. AGY CLI를 다시 열어 상태가 바뀐 후 파일이 갱신되어야 최신 값이 표시됩니다. `/usage`는 [공식 문서](https://antigravity.google/docs/cli/commands/usage)상 대화형 화면이며 Tokenly의 자동 조회 경로가 아닙니다. 한 버킷의 0%는 해당 버킷의 소진값으로, 연결 오류와 구분합니다.

이 안내 문구를 처음 포함한 당시 Release 앱은 `/private/tmp/tokenly-agy-stale-release/Build/Products/Release/Tokenly.app`에 생성됐습니다. 현재 점검 빌드 위치는 위 실행 절을 참고하세요. 당시 작업 샌드박스에서는 XCTest 실행이 차단됐으나 이후 사용자 Xcode에서 33개 모두 통과했습니다. 새 AGY 문구의 실제 GUI는 확인 전입니다. 기존 설치 앱과 `dist`는 변경하지 않았습니다.

## 현재 회귀 검증

이전 빌드에서 팝오버 최상위 `ScrollView`와 함께 메뉴 막대 클릭 후 상세 창이 보이지 않는 현상이 보고됐습니다. 현재 UI는 루트 `VStack`을 유지하고 AGY 버킷이 3개 이상일 때 그 목록만 높이 제한 스크롤로 표시합니다. 화면이 작고 두 Provider를 모두 펼쳤을 때는 Provider 영역에도 높이 제한 스크롤을 적용합니다. 사용자는 **팝오버 열림, AGY 접기/펼치기와 높이 축소, Codex 표시**를 실제 GUI에서 확인했습니다. 두 Provider 동시 펼침의 창 높이, 설정 창 왕복, 새 stale 문구는 추가 확인이 필요합니다. `/Applications` 앱과 기존 `dist`는 교체하지 않았습니다.
