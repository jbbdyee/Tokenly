# Tokenly 제품 사양 (가칭)

> **격리 앱 검증 범위(2026-10-30):** 별도 번들 ID의 Debug 앱을 실제 macOS 프로세스로 실행했다. 실제 홈 접근을 차단하고 실패 전용 임시 CLI를 사용했으므로, 이 실행은 서버 성공 조회나 실제 사용량 화면의 증거가 아니다. 1분 조건과 5분 실패 재시도는 `UsageStore` 자동 테스트 및 격리 프로세스 관찰 결과를 구분해 `HANDOFF.md`에 기록한다.

> **실제 인증 검증 보류:** 홈 쓰기를 차단하고 `.codex` 읽기만 허용하면 공식 Codex app-server가 초기 응답 전에 권한 오류로 종료한다. 기존 설정·로그인 상태의 불변성을 보장하는 격리 방법이 확인되기 전까지 성공 조회와 성공 후 60초 갱신을 실측 완료로 취급하지 않는다.

> **오류 조사 진전:** 첫 차단은 `.codex` 아래 SQLite 상태 DB 초기화였다. 공식 `sqlite_home`으로 이를 임시 경로에 옮겨도 별도의 EPERM이 남는다. 빈 임시 Codex 홈에서는 initialize가 성공했으므로 실계정 읽기 전용 경로의 추가 제약을 확인해야 한다.

> **현재 앱 상태(2026-10-28):** 이 문서의 곰돌이형 관련 절은 당시 디자인·검증 기록이다. Stage 6-6에서 메뉴 막대 스타일은 숫자형·최소형만 지원하고, 저장된 곰돌이형은 숫자형으로 전환한다. Stage 6-6B에서 전용 제품 코드·에셋을 삭제했으며 `Preview/Heart3D/` 제작 자료는 보존했다. 최신 System Monitor UI와 실기기 검증 상태는 `SYSTEM-MONITOR.md` 및 `HANDOFF.md`를 참조한다.

## 1. 개요와 목표

Tokenly는 macOS 메뉴 막대에서 **여러 AI 서비스의 사용량과 잔여 한도**를 한곳에서 확인하는 독립적인 네이티브 앱이다. 사용자는 **Codex와 Google Antigravity(AGY)의 실제 한도 표시 성공**, 아코디언 팝오버 열림·AGY 접기/펼치기를 보고했다. AGY 최신 수신이 끊겼을 때의 새 안내 문구는 GUI 미검증이다. OpenAI API 연동은 보류 중이며 Claude 구독 한도와 Gemini는 자동 조회를 지원한다고 확정하지 않는다. AGY는 Gemini API나 Gemini CLI와 별도 서비스로 다룬다. Routine Scout의 코드·캐릭터·디자인·설정은 재사용하지 않는다. 이전에 확인한 수치는 앱에 고정하지 않는다.

**독립 자동 조회 조사(2026-10-30):** 현재 Claude·AGY 구현은 상태줄 파일을 5분마다 재읽는다. Claude Code 개인 구독의 공식 비대화형 최신 한도 조회 계약은 확인되지 않았다. AGY 공식 변경 기록에는 v1.1.10부터 read-only `agy -p "/usage" --output-format json`이 모델 턴·쿼터 소비 없이 구조화된 결과를 반환한다고 명시돼 있다. 설치본 v1.4.10의 실제 JSON·인증/설정 영향은 아직 실행 검증하지 않았으므로 구현 완료 또는 지원 확정으로 표시하지 않는다. 세부 근거는 `IMP-PLAN.md` 78절과 `BLOG-NOTES.md`를 따른다.

## 2. 핵심 사용자 시나리오

1. 사용자가 메뉴 막대 아이콘을 열어 서비스별 조회 시각과 사용 가능한 지표를 확인한다. 1차에는 Codex만 보인다.
2. 제공되는 경우 5시간 창과 주간 창의 사용 비율·잔여 비율·초기화 시각을 확인한다.
3. 새로고침에 실패하거나 창 데이터가 없으면 원인을 구분한 안내를 보고 수동 재시도한다.
4. 창이 제공되지 않는 요금제·인증 방식이면 임의의 `0%`를 표시하지 않고 `제공되지 않음`으로 표시한다.

## 3. MVP 범위와 결정 조건

### 1차 MVP: Codex 한도 표시

- macOS 메뉴 막대에 `MenuBarExtra`를 표시하고, 앱이 실행 중임을 알아볼 수 있게 한다.
- 검증된 **읽기 전용 데이터 경로**에서 받은 한도 창만 표시한다. 응답의 `usedPercent`가 유효할 때 `남은 비율 = 100 − 사용 비율`로 계산하되, 범위를 벗어나거나 값이 없으면 미확인 상태로 둔다.
- 각 창의 실제 `windowDurationMins`를 확인해 5시간·주간 여부를 구분한다. `primary`가 항상 5시간, `secondary`가 항상 주간이라고 가정하지 않는다.
- 유효한 `resetsAt`가 있을 때만 사용자 현지 시간으로 초기화 시각을 표시한다.
- 수동 새로고침, 마지막 성공 시각, 조회 중·데이터 없음·인증 필요·일시적 실패 상태를 제공한다.
- 자동 새로고침은 검증된 소스의 호출 제약을 확인한 후 보수적인 간격으로 제공하고, 중복 호출을 막는다.
- **차기 버전 구현(설치본 v0.2.0에는 미적용):** Codex 타이머는 60초마다 갱신 가능 여부를 확인한다. AI 팝오버 열림·절전 복귀도 마지막 성공 조회와 최근 시도가 각각 60초 이상 전일 때만 새 조회를 시작한다. 진행 중 요청은 중복하지 않는다. 자동 조회가 실패하면 타이머의 다음 재시도는 최근 시도 후 300초 이상 기다려 CLI 실행을 제한한다. 팝오버·복귀 조건부 조회의 60초 제한과 수동 새로고침은 유지한다. 실패 뒤에는 마지막 성공값과 시각을 보존한다. Claude·AGY의 300초 상태줄 파일 재읽기 주기는 변경하지 않는다. 새 경로의 실제 팝오버 조작·절전 복귀 동작은 자동 테스트와 구분해 후속 실기기 확인이 필요하다.
- **차기 버전 표시 문구:** Codex의 마지막 성공 조회 시각을 팝오버와 설정에서 `마지막 갱신 시간`으로 표시한다. 실패 시 이전 성공 시각을 유지한다. 이는 Tokenly가 성공적으로 조회한 시각이며 서비스 서버의 집계 시각이 아니다. Claude·AGY의 `마지막 수신`은 상태줄 이벤트 시각을 뜻하므로 별도로 유지한다.
- Xcode 없이 실행할 수 있는 macOS `.app` 번들을 제공한다. 앱 번들은 CLI나 인증정보를 포함하지 않는다. 메뉴 막대 전용으로 실행하며 Dock 아이콘과 빈 창을 표시하지 않는다.
- 로그인 시 자동 실행은 처음에는 꺼져 있고 사용자가 설치된 앱의 설정을 조작할 때만 등록·해제한다. 현재 상태, 승인 필요, 등록 실패를 구분한다.

**검증 상태:** 일반 사용자 터미널의 공식 app-server 조회와 현재 텍스트 기반 메뉴 막대의 두 한도 표시를 사용자가 확인했다. 캡슐형 라벨은 실제 GUI에서 아이콘과 `5h`만 표시되는 오류가 확인되어 제거했다. 단일 `Text`의 부분 글꼴 스타일은 실제 GUI에서 눈에 띄는 차이가 없었다. 현재 텍스트 표시를 안정적인 기본 방식으로 유지한다. 누락·이전 데이터 등 개별 상태의 실제 GUI 확인은 별도로 남아 있다. 데이터가 없는데 수치를 추정하거나 다른 계정·API 사용량을 Codex 잔여 비율로 대체하지 않는다.

서비스별 Provider는 자기 서비스의 인증 경계, 조회 방식, 갱신 주기와 지표 종류를 책임진다. 공통 화면 모델에는 **서비스명·지표 종류·단위·값·조회 시각·상태**를 구분해 전달한다. 토큰 사용량, 구독 사용 한도, API 비용은 단위와 의미가 달라 합산하거나 하나의 잔여 비율로 환산하지 않는다. Provider 인터페이스는 1차에 필요한 최소 형태로 시작하고, 둘째 서비스의 실제 계약을 확인한 뒤 확장한다.

### 추후 확장

- 사용량 부족 알림과 임계값 설정. 알림 권한, 중복 알림 방지, 창 재설정 처리 검증 후 진행한다.
- 여러 한도 버킷 또는 요금제별 표시가 실제 응답에 존재할 경우 선택 UI 검토.
- Claude 구독은 공식 Claude Code 상태줄 JSON 계약을 확인했지만 실제 계정 수신·앱 연동은 미검증이다. Gemini는 자동 조회 계약 검증 단계, OpenAI API는 코드가 있지만 연결 보류다. AGY는 사용자가 실제 한도 표시 성공을 보고했다.
- 메뉴 막대 테마 선택 후보: 숫자형, 작은 아이콘과 사용량을 함께 보여 주는 아이콘형, 캐릭터 상태를 사용하는 캐릭터형, 공간을 최소화하는 미니멀형. 현재 숫자형·최소형·아이콘형과 시스템/라이트/다크 외관 설정을 구현했으며 캐릭터형은 후속이다.
- 테마 구현 전에 AppKit `NSStatusItem`·`NSStatusBarButton`의 속성 문자열 또는 사용자 지정 뷰 방식을 기술 검증 후보로 비교한다. 현재 지원 방식으로 확정하지 않는다.
- Tokenly 전용 앱 아이콘: Routine Scout와 독립적인 디자인으로, 콘셉트 보드의 D안(세 개의 반투명 글래스 오브)을 채택해 앱에 등록했다(문서 끝 "앱 아이콘" 절).
- Provider 연동 가능성을 확인한 뒤 서비스별 지표와 로고를 구분하고 메뉴 막대 표시 대상을 선택할 수 있는 통합 UI를 설계한다. 시간 단위·잔여 비율의 시각적 구분은 macOS 제약을 확인하며 AppKit 방식도 기술 검증한다.

### 제외

- Codex 작업 실행·자동화, 채팅 내용·프롬프트·토큰 상세 기록 수집
- 한도 우회, 사용량 초기화 기능, 크레딧 구매·소비
- Routine Scout와 데이터·아이콘·캐릭터·디자인 공유
- 별도 로그인 구현과 인증정보 저장

## 4. 메뉴 막대 UI 요구사항

- 이전 빌드에서는 임시 시스템 아이콘과 단일 `Text` 라벨을 사용했다. 최신 구현은 문서 끝의 UI 절을 따른다. 실제 응답의 잔여 비율을 `5h 21% · 7d 16%` 형식으로 모두 표시한다. 숫자는 예시이며 고정하지 않는다. `5h`·`7d`에 적용한 작은 글꼴은 실제 GUI에서 기존 표시와 눈에 띄는 차이가 없었으므로 추가 SwiftUI 라벨 디자인 실험은 보류한다.
- 한도가 누락되면 해당 위치에 `—`를 표시한다. 메뉴 막대의 캡슐 그룹·개별 숫자 색상은 실제 GUI에서 표시 오류가 확인되어 현재 범위에서 제외하고 후속 기술 검증 항목으로 둔다.
- 누락 창은 `—`, 첫 조회 중·데이터 없음·조회 실패는 별도 문구, 실패 뒤 마지막 성공값은 `이전` 표기를 사용한다.
- 서비스별 카드 또는 행에 **지표 종류와 단위**를 명시한다. Codex 한도 창은 창 이름, 사용/잔여 비율, 초기화 시각을 읽기 쉽게 표시한다. 미확인 창은 별도 상태로 표시한다.
- 메뉴에서 수동 새로고침과 마지막 갱신 시각을 제공한다. 네트워크 오류 때 이전 성공값을 보여 준다면 반드시 `이전 데이터`와 시각을 함께 표시한다.
- 비율만으로 상태를 전달하지 않고 텍스트와 접근성 설명을 함께 제공한다.
- 팝오버는 라이트·다크 모드에 적응하는 시스템의 일반 재질(`regularMaterial`)로 부드러운 반투명 효과를 제공한다. 배경이 과도하게 비쳐 보조 정보가 흐려지지 않아야 하며, 제목·잔여 수치·사용량·초기화·마지막 성공 시각의 대비를 유지한다. 긴 초기화 시각은 별도 줄에서 줄바꿈할 수 있게 한다. 잔여 막대의 색상과 수치는 함께 유지한다.

### 현재 구현: 팝오버와 설정 창 분리

팝오버의 로그인 토글을 제거하고 별도 SwiftUI `Settings` 창으로 옮겼다. 팝오버에는 Codex 사용량·새로고침·설정 열기·종료를 둔다. 메뉴 막대 전용 앱과 현재 단일 텍스트 라벨은 유지한다. 설정 창 열림·포커스·재열기 등은 앱 빌드와 별도로 실제 GUI 검증이 필요하다.

- **팝오버:** 사용자가 표시하도록 선택한 지원 Provider의 사용량, 새로고침, `설정 열기`, 종료만 둔다. 자주 바꾸지 않는 로그인 시 자동 실행 토글은 설정 창으로 옮긴다.
- **별도 설정 창:** 일반 설정(로그인 시 자동 실행 포함), AI 서비스 관리, 메뉴 막대 표시 설정, 테마 및 디자인 설정을 구분한다. 창을 닫아도 메뉴 막대 앱은 계속 실행한다.
- **서비스 선택:** Codex·AGY의 팝오버 표시 여부를 `UserDefaults`에 저장하고 재실행 시 복원한다. Codex를 숨기면 그 영역을 제거하지만 기존 5분 조회와 메뉴 막대 수치는 유지한다. AGY는 상태줄 수신 파일이 있을 때만 표시 토글을 허용한다. 실제 응답이 없으면 설정 필요 또는 오류를 표시하며 `0%`를 만들지 않는다. 숨긴 AGY는 5분 자동 조회 대상에서 제외한다. OpenAI API는 연동 보류 중으로 기존 저장된 표시 선택값과 Provider 코드는 보존하되 설정·자동 조회·팝오버 표시를 중단한다. Claude·Gemini는 선택할 수 없다. 모든 서비스를 숨기면 안내를 표시하며 설정·종료 버튼은 남는다.
- **메뉴 막대 표시:** 설정 창에 현재 동작과 향후 선택 기능을 설명한다. 현재 숫자형·최소형·아이콘형과 1차 시제품인 하트형(문서 끝 절 참고)을 구현했다. 캐릭터형과 메뉴 막대 표시 Provider·지표 선택은 후속이다. 아무것도 선택하지 않거나 데이터가 없을 때에도 앱을 다시 열 수 있는 표시 수단이 필요하다. 서비스마다 지표 종류가 다르므로 모든 Provider에 5시간·7일 창을 요구하지 않는다.
- **초기값:** Codex의 팝오버 표시를 기본으로 켠다. 현재 기본 메뉴 막대 표시는 시스템 아이콘 없는 숫자형이다. 로그인 항목은 사용자 동의 없이 새로 등록하지 않으며 실제 시스템 등록 상태를 따른다. 설정 저장·재로드 코드는 추가했지만 실제 앱 재실행 GUI 검증은 남아 있다.
- SwiftUI `Settings` scene과 `openSettings`를 사용하고, 이미 보이는 설정 창은 같은 창을 앞으로 가져오도록 구성했다. `LSUIElement` 앱에서 실제 창·키보드 포커스·중복 방지를 설치된 앱의 GUI에서 확인해야 한다. 이전 캡슐형 표시 오류와 단일 `Text` 부분 글꼴의 미미한 차이를 고려해 테마 구현 전 AppKit `NSStatusItem` 방식을 기술 검증한다.

## 6. 개인정보와 인증정보 보호

- 공식 app-server를 기존 Codex CLI 프로세스로 호출하며 앱은 인증 파일을 직접 열지 않는다.
- 비밀번호·액세스 토큰·API 키·인증 파일 내용을 코드, 로그, 테스트 fixture, 문서, 저장소에 복사하지 않는다.
- 가능하면 기존 인증 상태를 공식 지원 경로로 사용하고, 앱이 로그인 정보를 직접 읽거나 재사용하지 않도록 한다. 실제 연동 방식은 보안 검토 후 결정한다.
- 표시와 오류 로그에는 비율, 창 길이, 초기화 시각 등 필요한 정보만 남기고 계정 식별자와 원시 응답은 저장하지 않는다.
- 인증이 필요하면 자동 로그인이나 권한 확대를 시도하지 않고 사용자에게 상태를 안내한다.

## 7. 성공 기준

1. 검증된 계정·데이터 소스로 실제 한도 창을 반복 조회하고, 공식 표시값과 의미가 일치한다.
2. 존재하는 창만 정확한 이름·비율·초기화 시각으로 표시하며, 빠진 창은 미제공 상태로 보인다.
3. 수동·자동 새로고침과 실패·데이터 없음 상태가 테스트와 macOS 실제 실행에서 확인된다.
4. 인증정보 노출이나 Routine Scout 변경 없이 Tokenly의 별도 Xcode 프로젝트로 빌드·실행된다.

## 8. 현재 확인 상태

2026-10-22 일반 macOS 사용자 터미널에서 `initialize` → `initialized` → `account/rateLimits/read` 호출로 **한도 버킷 1개와 조회 완료**를 확인했다. 300분 창은 사용 35%·잔여 65%·초기화 2026-10-23 01:42 KST, 10080분 창은 사용 77%·잔여 23%·초기화 2026-10-27 15:47 KST였다. 이 값은 당시의 확인 기록이며 실행 중에는 응답에서 새로 읽는다. Codex CLI는 `0.163.0-alpha.10.2`였다. 사용자는 현재 텍스트형 메뉴 막대의 두 한도 표시를 실제 GUI에서 확인했다. 캡슐형은 표시 오류가 있었고 부분 글꼴 스타일의 시각적 차이는 미미했다. 누락·이전 데이터 상태 등은 빌드·XCTest와 실제 GUI 검증을 구분한다.

독립 실행용 Release `.app` 번들은 프로젝트의 `dist`에 생성했다. 사용자는 `/Applications`에 설치한 앱을 Xcode 없이 실행해 실제 Codex 사용량 조회 성공을 확인했다. CLI 탐색은 프로세스 `PATH`와 일반 설치 경로를 확인하며, 실제 선택 경로는 미확인이다. 로그인 항목은 Apple `SMAppService.mainApp`을 사용한다. 최초 상태 조회 실패의 원인은 미확정이다. 이후 사용자가 macOS 시스템 설정에서 직접 로그인 항목에 추가하자 앱은 `켜짐 · 다음 로그인부터 실행됩니다.`를 표시했다. 앱 내부 토글의 신규 등록·해제와 재로그인 후 자동 실행은 미검증이다.

## 9. 추가 Provider의 현재 계약과 상태

| 서비스 | 구현된 조회 경로 | 표시 가능한 지표 | 실제 계정 검증 |
| --- | --- | --- | --- |
| Claude 구독 | 공식 Claude Code 상태줄 JSON의 구독 `rate_limits`만 추리는 브리지와 로컬 파일 Provider 구현. 사용자 설정에 상태줄 명령은 아직 연결하지 않음 | 파일 수신 시 5시간·7일 잔여율·초기화·수신 시각; 현재 실제 계정값 없음 | 실제 계정 상태줄 수신·GUI 미검증 |

| Gemini | 기존 공식 대시보드·CLI 조사만 유지 | 앱 조회 없음 | 미검증 |

AGY IDE와 AGY CLI를 구분한다. CLI의 `/usage`·`/quota`는 대화형 화면이어서 자동 조회 계약으로 사용하지 않는다. 상태줄 계약은 CLI가 실행 중일 때 JSON을 **푸시**하므로 Tokenly가 임의 시점에 갱신을 강제할 수 없다. 브리지는 이메일·세션 ID·작업 경로를 버리고 모델/버킷 키와 쿼터 값만 파일에 기록한다. 사용자가 기존 AGY 상태줄 명령을 교체·연결해야 하며 Tokenly는 이를 자동 수정하지 않는다. [AGY 상태줄 공식 문서](https://antigravity.google/docs/cli/statusline), [AGY `/usage` 문서](https://antigravity.google/docs/cli/commands/usage).

OpenAI API 조회는 관리자 권한이 필요하다. 일반 `sk-` API 키는 저장·호출 대상에서 제외한다. 사용량은 Completions 범위이고 비용은 조직 전체 범위라 합산하거나 동일 범위인 것처럼 표현하지 않는다. 두 응답의 페이지를 처리하고 서버 본문·키를 로그에 남기지 않는다. 조회 실패는 인증 누락, 403 권한 오류, 타임아웃, 네트워크 오류, 응답 오류로 구분한다. [OpenAI Usage GET](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/completions), [OpenAI Costs GET](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/costs), [관리자 키 설명](https://platform.openai.com/docs/api-reference/admin-api-keys).

Claude Code의 대화형 사용량 화면을 비공식적으로 자동 파싱하거나 인증 파일·브라우저 쿠키를 읽지 않는다. [공식 상태줄 JSON](https://code.claude.com/docs/en/statusline)은 Pro/Max 구독 세션의 첫 API 응답 이후 `rate_limits.five_hour`·`seven_day` 각각에 `used_percentage`(0–100)와 `resets_at`(Unix 초)을 제공할 수 있다. 창은 개별적으로 빠질 수 있고 초기화 시각이 지나면 제거된다. 따라서 구독 결제 사실만으로 현재 값이 수신된다고 가정하지 않는다. Claude 조직 API의 토큰·비용 보고는 개인 구독 잔여 한도와 다르다. [Claude Usage and Cost Admin API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api).

## 10. 2026-10-23 팝오버 회귀 및 AGY 연결 상태

당시 사용자 GUI에서 메뉴 막대 수치는 보이지만 클릭 시 상세 팝오버가 열리지 않는 회귀가 확인됐다. 최근 팝오버 루트를 높이 미지정 `ScrollView`로 바꾼 부분을 이전의 고정 폭 `VStack`으로 되돌려 `.regularMaterial`과 상세 정보·설정 버튼을 유지했다. 이는 레이아웃 원인에 대한 유력한 수정이나, 실제 팝오버 열림·설정 창 포커스·재실행은 새 빌드의 GUI 확인 전까지 미검증이다. 설치 앱과 개발 앱의 중복 실행 및 화면 밖 표시 여부도 확인하지 못했다.

**당시 기록:** AGY 설정은 `statusLine` 부재·유효한 JSON·권한 `0600`을 재확인했으나 작업 환경이 홈 디렉터리 백업 생성을 거부하여 그 작업에서는 쿼터를 받지 못했다. 이후 사용자는 Codex·AGY의 실제 한도 표시 성공을 보고했다. `enable_agy_statusline.py`는 재확인·0600 백업·기존 설정 보존·JSON 검증을 위한 도구로 남아 있다.

## 11. Provider 아코디언과 팝오버 (2026-10-23)

Codex와 AGY는 각각 접고 펼친다. 기본값은 Codex 펼침, AGY 접힘이며 `UserDefaults`에 독립적으로 저장한다. 접은 상태에서도 Provider 이름·잔여 한도 요약·chevron·오류/소진 상태를 볼 수 있다. 펼치면 개별 한도, 잔여 막대, 제공된 사용 비율·초기화 시각, 마지막 성공 시각, 서비스별 새로고침과 오류를 표시한다. 접기 상태는 조회와 5분 자동 갱신에 영향을 주지 않는다. 설정에서 숨긴 Provider는 표시하지 않는다.

AGY는 **하나의 버킷을 전체 서비스의 대표값으로 선택하지 않는다.** 버킷이 하나면 원본 ID와 해당 비율을 표시하고, 둘 이상이면 `N개 버킷 · 최저–최고%` 범위를 표시한다. 예를 들어 `3p-weekly` 100%, `gemini-weekly` 0%는 `2개 버킷 · 0–100%`와 `일부 버킷 소진`으로 표현한다. 내부 ID의 정확한 사용자용 의미가 공식 자료에서 확인되지 않아 원문을 유지하며, UI 이름 매핑은 별도 함수로 분리한다. [AGY 상태줄 계약](https://antigravity.google/docs/cli/statusline)은 이를 모델/버킷 ID로 설명한다.

팝오버 최상위는 고정 폭 `VStack`과 `.regularMaterial`로 유지한다. 전체를 무제한 `ScrollView`로 감싸지 않는다. AGY 버킷이 3개 이상일 때에만 해당 버킷 목록을 화면 높이에 맞춘 제한된 스크롤로 표시한다. 두 Provider가 모두 접히면 요약 행만 남고, 모두 펼치면 개별 행이 나타난다. 사용자는 메뉴 막대 클릭, AGY 접기/펼치기와 접힌 높이 축소를 확인했다. 두 Provider 동시 펼침의 화면 내 표시, 설정 창 왕복과 라이트·다크 모드의 시각적 결과는 추가 확인이 필요하다.

## 12. AGY 상태줄 수신과 만료 상태 (2026-10-23)

사용자는 아코디언 빌드의 팝오버 열림, AGY 접기/펼치기와 높이 축소, Codex 표시를 실제 GUI에서 확인했다. AGY는 이전에 실제 쿼터를 표시했으나 현재 `조회 불가`와 오래된 데이터 안내가 나타난다고 보고했다.

읽기 전용 점검에서 AGY `statusLine` 설정은 활성 상태이며 브리지 명령 경로도 존재했다. 브리지는 공식 상태줄 JSON에서 유효한 `quota`만 추출해 `~/Library/Application Support/Tokenly/agy-quota.json`에 수신 시각과 함께 저장한다. 당시 파일에는 두 유효한 버킷과 초기화 시각이 있었지만 마지막 수신 후 약 7시간 20분이 지나 있었다. Provider는 수신 후 **15분**을 넘으면 `.staleData`를 반환한다. AGY CLI가 종료됐거나 실행 중이어도 새 상태 변화 이벤트가 없으면 파일은 갱신되지 않는다. Tokenly의 5분 자동 새로고침은 이 **로컬 파일을 다시 읽는 것**이며 AGY 백엔드 쿼터를 직접 갱신하지 않는다. [AGY 상태줄 계약](https://antigravity.google/docs/cli/statusline)은 상태 변화 시 푸시를 설명하며, [공식 `/usage`](https://antigravity.google/docs/cli/commands/usage)는 대화형 패널이다. 현재 확인한 범위에는 안전한 비대화형 최신 쿼터 조회 계약이 없다.

현재 정책은 만료된 비율을 **최신 수치처럼** 표시하지 않는 것이다. 앱이 이미 정상 값을 메모리에 가진 뒤 만료되면 `이전 데이터`와 마지막 성공 시각을 붙여 보여 준다. 재실행 후에는 메모리의 이전 값이 없어 만료 파일만으로 비율을 복원하지 않는다. 이번 수정은 이 정책을 바꾸지 않고 이전 값이 없는 stale 상태의 접힌 요약을 `최신 데이터 없음`, 상태를 `상태줄 갱신 대기`로 명확히 하며 상세 안내에 15분 기준과 가능한 원인을 적었다. 한 버킷이 0%이고 다른 버킷이 양수인 것은 **유효한 수신 데이터**이며 stale 또는 브리지 오류로 분류하지 않는다. 재실행 후에도 만료 파일의 마지막 비율을 시각과 함께 표시하는 안은 오해 위험이 있어 별도 결정 전까지 보류한다. 새 문구의 실제 GUI는 미검증이다.

변경 후 Debug·Release 앱과 테스트 타깃 빌드는 성공했다. XCTest 실행은 작업 샌드박스의 테스트 서비스 제한으로 중단되어 통과 미확인이다. 새 stale 문구, AGY CLI 재실행 뒤의 데이터 갱신은 사용자 GUI 확인이 필요하다.

## 최신 UI 요구사항 및 구현 상태 (2026-10-23)

이 절이 위의 과거 메뉴 막대 아이콘·테마 보류 설명보다 최신이다. 메뉴 막대 스타일은 `UserDefaults`에 저장하며 기본 **숫자형**은 아이콘 없는 단일 `Text`로 `5h 82% · 7d 97%`처럼 표시한다. **최소형**은 `82% · 97%`, **아이콘형**은 `bolt.fill`과 5시간 잔여율을 표시한다. 5시간 창이 없고 7일 창만 있으면 아이콘형에 `7d`를 명시한다. 숫자는 실제 Codex 응답에서 계산한다. 누락값은 `—`, 첫 조회 중·데이터 없음·조회 실패는 문구, 실패 후 보존값은 `이전 ·`으로 구분한다. 선택 즉시 반영하고 재실행 시 복원하도록 구현했다. 사용자는 세 스타일의 실제 표시와 클릭을 확인했다. 좁은 메뉴 막대와 오류 문구에서의 잘림은 별도 확인이 필요하다. 과거 캡슐형은 표시 오류, 부분별 글꼴은 가시 효과가 거의 없었으므로 재사용하지 않는다.

팝오버는 최상위 `VStack`·`.regularMaterial`과 Codex 기본 펼침·AGY 기본 접힘을 유지한다. 새로고침은 상단 하나만 제공하며 Codex는 공식 app-server를 조회하고 AGY는 **로컬 상태줄 수신 파일을 다시 읽는다**. 반복적인 Provider 설명과 각 Provider의 새로고침 버튼은 제거했다. 마지막 성공·수신·초기화 시각은 시스템 로케일·시간대에 따라 오늘/내일 또는 간결한 날짜와 시간으로 표시하고 전체 날짜는 툴팁에 둔다. 연도가 달라지면 연도를 표시한다. AGY 복수 버킷은 합산하거나 한 버킷을 전체 대표값으로 삼지 않는다. 일반 화면에서는 AGY 목록에만 높이 제한 스크롤을 둔다. 가용 높이가 650pt 미만이고 두 Provider가 모두 펼쳐졌을 때는 Provider 영역에도 명시적 높이 제한 스크롤을 둔다. 최상위는 계속 `VStack`이다.

설정 창 네 탭을 유지한다. 일반 탭은 기존 로그인 항목 상태와 개발 빌드·Applications 설치본 차이를 안내한다. AI 서비스는 Codex·AGY 표시와 조회·마지막 성공/수신 상태, Claude·Gemini 후보, OpenAI API 연결 보류를 간결하게 보여 준다. 메뉴 막대 탭은 세 스타일과 실제 현재 값의 미리보기를 제공한다. 테마 탭은 **시스템 설정 따르기(기본), 라이트, 다크** 중 하나를 저장해 팝오버와 설정 창에 적용한다. 메뉴 막대 자체의 외관은 macOS가 제어한다. 캐릭터형·전용 아이콘·메뉴 막대 Provider 선택·AppKit 상태 막대 검증은 후속 과제다.

## v1 검증 상태와 안정화 기준 (2026-10-23)

사용자는 실제 macOS GUI에서 메뉴 막대 세 스타일의 표시·팝오버 열기, 간결화 팝오버와 통합 새로고침 버튼, 설정 창 네 탭, 스타일·테마 즉시 적용, 재실행 후 설정 복원을 확인했다. 별도로 **일반 사용자 Xcode에서 기존 XCTest 33개가 실제 실행되어 모두 통과했고 코드 커버리지 54%**라고 보고했다. 이 결과는 Claude 구현 전 결과다. 새 Claude 테스트는 앱·테스트 타깃 컴파일까지 확인했고 샌드박스 테스트 서비스 제한으로 실제 실행하지 못했다.

배포 전에는 Codex 미로그인·인증 만료·재시도, AGY 파일 없음·0%·15분 만료·새 상태줄 수신, 자동 갱신 중 반응성, 팝오버 반복 조작, 설정 창 중복·재열기, 로그인 항목 등록·해제와 재로그인, 개발본·설치본 동시 실행, 작은 화면과 라이트·다크 대비를 각각 확인한다. 코드상 오류·빈 상태와 이전 데이터 표시는 유지하고, 실제 계정 사용량을 추정해 채우지 않는다.

## Claude 구독 상태줄 연동 준비 (2026-10-23)

공식 [Claude Code 상태줄](https://code.claude.com/docs/en/statusline)의 `rate_limits.five_hour`·`seven_day`만 받는 브리지를 앱 번들 리소스로 추가했다. 브리지는 사용률(0–100)·Unix 초 초기화 시각·로컬 수신 시각만 권한 0600의 `~/Library/Application Support/Tokenly/claude-quota.json`에 기록한다. 계정·세션·경로·대화·인증 필드와 원본 JSON은 저장하지 않는다. 각 창의 잔여율은 `100 − used_percentage`이며 없는 창은 0%로 만들지 않는다. 초기화 시각이 지난 창은 제외한다. 파일이 없으면 연결 설정 필요, 유효한 창이 없으면 데이터 없음, 마지막 수신 후 15분을 넘으면 오래된 데이터로 구분한다. **15분은 실제 이벤트 주기 검증 전의 보수적인 임시 기준**이다. 사용자가 이전 값을 보더라도 마지막 수신 시각과 이전 데이터 표시가 따른다.

Claude는 Codex·AGY와 독립적인 Provider와 아코디언 상태를 갖는다. 팝오버 표시·접기 설정은 `UserDefaults`에 저장하며 기본값은 둘 다 꺼짐이다. 기존 Codex 메뉴 막대 라벨은 그대로다. 상단·5분 갱신에서 Claude는 **로컬 파일만 다시 읽고** Claude 서비스에 직접 사용량을 요청하지 않는다. 사용자 설정의 `statusLine` 추가, 실제 계정 데이터 수신, GUI 확인은 아직 수행하지 않았다. Anthropic API 사용량·비용과 구독 한도를 합산하지 않는다.

사용자가 설정 변경을 승인했으나 이 작업 샌드박스는 `~/.claude`의 0600 백업 생성부터 `Operation not permitted`로 거부했다. 변경 직전 확인한 `settings.json`은 유효한 JSON, `statusLine` 없음, 권한 0644였다. 원본과 인증 상태는 변경하지 않았다. 일반 사용자 터미널용 설정 도구는 실행 직전에 같은 조건을 재확인하고 기존 키를 보존하며 0600 백업을 만든 뒤 설정 권한을 0600으로 강화한다. 현재 **실제 백업 경로는 아직 없고 실제 계정 수신도 성공하지 않았다.**

## 팝오버 Provider 표시 순서 (2026-10-23)

팝오버의 Provider 영역은 **Codex → Claude → Google Antigravity** 순서로 표시한다. 숨긴 Provider는 건너뛰며, 구분선은 실제로 표시되는 영역 사이에만 둔다. 표시 여부·아코디언 펼침 상태의 `UserDefaults` 키와 저장 방식, 사용량 조회, 메뉴 막대 스타일은 바꾸지 않는다. 새 순서의 GUI 확인은 아직 하지 않았다.

## 하트 게이지 UI 1차 시제품 (2026-10-23, GUI 피드백 반영)

메뉴 막대 표시 스타일에 **하트형**을 네 번째 선택지로 둔다. 기존 숫자형·최소형·아이콘형과 기본값(숫자형)은 그대로이며 기존 저장값을 하트형으로 바꾸지 않는다. 하트는 **메뉴 막대에서만** 사용한다. 1차 시제품의 팝오버 상단 큰 하트 대시보드는 사용자 GUI 확인 후 제거했다. 팝오버는 헤더 → Codex·Claude·Google Antigravity 아코디언 → 하단 상태로 원래 구성을 유지한다.

- **모양:** 1차 시제품의 젤리 하트(모양·색상·광택·그라데이션·테두리·그림자)를 그대로 쓴다. 색상은 Codex 코랄 핑크, Claude 라벤더, AGY 하늘색이다.
- **메뉴 막대 배치:** Codex → Claude → AGY 순서로 하트를 놓는다. 각 하트 **안**에 잔여율(`30%`), 바로 **아래**에 짧은 이름(`Codex`·`Claude`·`AGY`)을 둔다. 상태 항목 높이 22pt 안에 맞추기 위해 하트 폭 18pt(높이 약 15.8pt), 숫자 6.5pt(`100%`는 5.4pt), 이름 6pt로 정했다. 하트 사이 간격은 8pt(`MenuBarHeartRow.heartSpacing`)다. 이름 줄 상자는 하트와 0.25pt만 겹치고(`MenuBarHeart.nameSpacing`), 이름 아래의 빈 1.9pt 중 1.6pt를 잘라 높이를 확보한다(`nameBottomTrim`). 이미지 높이는 21.99pt이고, 너비는 하트 3개 79pt, 2개 53pt, 1개 20–22.5pt(이름 길이에 따름)다.
- **대표값:** 서비스의 유효한 잔여율 중 가장 낮은 값을 0–100으로 제한해 쓴다. AGY는 수신 버킷의 최저값이며 Gemini 구독 전체 사용량으로 해석하지 않는다.
- **상태별 표시:**
  - 최신 데이터는 서비스 색 하트와 잔여율로 표시한다. 0%는 숨기지 않고 빈 하트에 `0%`를 표시한다.
  - 이전에 유효한 값을 받았지만 현재 조회가 실패했거나 stale이면 회색 하트에 마지막으로 받은 유효 잔여율을 표시한다. 이름도 회색이다.
  - 표시를 끈 서비스, 수신 파일이 없는(연결 안 됨) 서비스, 유효한 값을 받은 적이 없는 서비스는 하트를 숨긴다.
  - 표시할 하트가 없으면 시스템 템플릿 `heart` 아이콘만 남겨 팝오버를 열 수 있게 한다.
- **수신 이력의 근거:** 추정하지 않고 다음 두 가지만 사용한다.
  - 이번 실행 중 실제 성공한 조회
  - 상태줄 브리지가 저장한 로컬 수신 파일(`agy-quota.json`, `claude-quota.json`)에 남아 있는 유효 값(나이 무관)

  AGY 상태줄이 잠시 멈춰 15분 기준을 넘어도, 파일에 유효 값이 있으면 연결 해제가 아니라 회색 하트로 남긴다. Codex는 저장 파일이 없으므로 이번 실행 중 받은 값만 이력으로 본다. Claude 브리지가 두 창이 모두 빠진 이벤트를 빈 값으로 덮어쓰면, 그 이전 이력은 파일로 알 수 없다.
- 기존 조회·갱신 주기·15분 stale 판정은 바꾸지 않는다.

구현과 Debug·Release 빌드, XCTest 45개 통과를 확인했다. 실제 계정 데이터 표시와 메뉴 막대 GUI·클릭은 **사용자 확인 전**이다.

### 메뉴 막대 하트 글자 가독성 시안 비교 (진행 중, 앱 미적용)

사용자가 현재 하트가 오래된 이모티콘·플라스틱 장난감처럼 보인다고 보고했다. A(현재), B(소프트 3D), C(글래스 젤리) 비교 이미지를 `Preview/HeartStyles/`에 만들었다. **앱의 하트는 바꾸지 않았다.**
- 세 시안은 하트 폭 18pt, 간격 8pt, 이름 여백, 아래에서 채우는 게이지를 공유한다.
- B·C의 숫자·이름은 가독성 시안 C의 숫자, B의 이름 처리를 따른다.

## 곰돌이형 메뉴 막대 스타일 (2026-10-23, 앱 적용)

## Codex 사용 한도 재설정 권한 표시 (2026-10-23, 앱 적용·읽기 전용)

**조사 결과:** 공식 경로에서 조회할 수 있다.
- 근거는 설치된 `codex-cli 0.163.0-alpha.10.2`가 생성한 공식 프로토콜 스키마(`codex app-server generate-json-schema`)다. Tokenly가 이미 쓰는 읽기 전용 `account/rateLimits/read` 응답의 `GetAccountRateLimitsResponse`에 선택 필드 `rateLimitResetCredits`(`RateLimitResetCreditsSummary`)가 있다.
- 필드 구성: `availableCount`와 `credits[]`(`expiresAt` 유닉스 초 또는 `null`=만료 없음, `status` available/redeeming/redeemed/unknown, `resetType`, `title` 등). `credits`가 `null`이면 횟수만 알려진 것이고, 목록은 백엔드가 줄일 수 있다.
- 실제 계정에서 같은 읽기 요청을 한 번 보내 필드가 채워지는 것을 확인했다(2회, 상세 2건, 만료 일시 있음). 계정 ID·권한 ID는 출력하지 않았다.
- 권한을 **소모하는** `account/rateLimitResetCredit/consume`은 쓰지 않는다. 비공식 API·쿠키·토큰 추출·브라우저 자동화도 쓰지 않았다.

**표시:**
- 팝오버 Codex 아코디언을 **펼쳤을 때만**, 5시간·7일 한도 아래에 "사용 한도 재설정"과 "N회 사용 가능"(없으면 "사용 가능 없음")을 보인다.

**검증 상태:** 공식 스키마·실제 응답 확인, 구현, Debug·Release 빌드, XCTest 58개 통과, 앱 팝오버 코드의 오프라인 렌더링(펼침/접힘)을 확인했다. 실제 메뉴 막대 팝오버에서의 표시·스크롤은 **사용자 확인 전**이다.

- Asset Catalog `src/Tokenly/Assets.xcassets`의 `AppIcon`(macOS 16·32·128·256·512pt × 1x·2x)으로 등록했다.
- Info.plist에 `LSApplicationCategoryType = public.app-category.utilities`를 지정한다(macOS 앱 목록의 카테고리 분류용, 2026-10-24).
- **앱 목록 표시:** 메뉴 막대 전용 앱이라 Dock에 나타나지 않으므로 macOS 앱 목록(`Apps.app`)의 전체·유틸리티 목록에 계속 표시돼야 한다. 2026-10-24 설치 후 앱 목록에서 사라지는 문제가 있었고, 진단 실험 뒤 다시 표시되며 유지되는 것을 사용자가 확인했다. 해결 원인은 확인되지 않았다(IMP-PLAN 46절). 외부 배포 전에 새 Mac·Developer ID 서명 빌드·재로그인 후 표시를 확인한다.
- 메뉴 막대 전용 앱(`LSUIElement`)이라 평소에는 Dock에 아이콘이 나타나지 않는다. 아이콘은 Finder·응용 프로그램 폴더·Launchpad·설정 창 등에서 쓰인다.
- macOS 27의 시스템 아이콘 서비스는 이 아이콘을 표준 둥근 사각형으로 다시 마스킹하고 약간 확대하며 가장자리 광택을 더해 표시한다(회색 틀에 넣지는 않음). 따라서 Finder 등에서는 원본 배경판 모서리 대신 시스템 곡선이 보인다.

## v0.1.0 공개 준비 방향 (2026-10-24, 승인·구현 전)

첫 공개는 무료 ad-hoc 서명 GitHub Pre-release(개발자 미리보기)다. 공개 전에 번들 ID를 `io.github.jbbdyee.tokenly`로 바꾸고, Claude·AGY 수신을 Python(`/usr/bin/python3`) 대신 앱 실행 파일의 명령줄 모드(`Tokenly --statusline claude|agy`)로 처리한다. Claude의 기존 statusLine은 출력을 유지하고, CLI 설정 변경은 사용자가 직접 실행한 연결·해제 명령에서만 확인·백업 후 수행한다. 1단계 실행 가능성 검증은 통과했다(IMP-PLAN 47절). 2단계로 소스에 네이티브 브리지, 기존 statusLine 공존, `--status`·`--connect`·`--disconnect`를 구현하고 테스트했다(IMP-PLAN 48절). 3단계로 소스의 번들 ID를 `io.github.jbbdyee.tokenly`로 바꿨다(IMP-PLAN 49절). 아직 설치본에 반영하지 않았다.

## 명령줄 모드와 statusLine 연결 (2026-10-24, 소스 구현·설치 전)

- `Tokenly --statusline claude|agy`: Claude Code·AGY가 상태줄 JSON을 표준입력으로 넘겨 실행한다. 허용 필드만 0600 파일로 저장하고, 연결 전에 쓰던 statusLine이 있으면 같은 입력으로 실행해 그 출력을 그대로 표시한다. Python이 필요 없다.
- `Tokenly --status`: 연결 상태와 마지막 수신 시각만 보여 준다.
- `Tokenly --connect claude|agy [--dry-run|--yes]`: 변경 내용을 보여 주고 확인을 받은 뒤 백업과 함께 연결한다. `/Applications` 또는 `~/Applications`에 설치한 앱에서만 실행한다.
- `Tokenly --disconnect claude|agy [--dry-run|--yes]`: Tokenly가 설치한 statusLine일 때만 연결 직전 상태로 되돌린다(없었으면 제거, 사용자 명령·0.1.0 Python 브리지 명령이었으면 원문 복원). 사용자가 나중에 바꾼 설정은 바꾸지 않는다. 연결 직전 값이 없는 이전 형식(v1) 기록은 연결 때 만든 백업으로 판정하고, 판정할 수 없거나 복원할 Python 파일이 없으면 아무것도 바꾸지 않고 중단한다.
- 설정 화면은 터미널 연결 명령을 복사만 하고 CLI 설정 파일을 직접 바꾸지 않는다.
- 기존 0.1.0 Python 브리지는 호환을 위해 앱에 남는다.

## 번들 ID (2026-10-24, 소스 적용·설치 전)

- 번들 ID는 `io.github.jbbdyee.tokenly`다(0.1.0 개발자 설치본은 `com.tokenly.app`).
- 설정은 번들 ID 도메인에 저장되므로 옛 설정은 자동으로 넘어오지 않는다. 개발자 Mac에서만 새 앱 첫 실행 전에 수동으로 옮긴다. 옮기지 않으면 Claude·AGY는 숨김, Codex는 표시로 시작한다.
- 로그인 시 실행은 새 앱에서 다시 켜야 한다. 옛 앱에서 먼저 꺼서 항목이 둘 남지 않게 한다.
- 수신 데이터 폴더(`~/Library/Application Support/Tokenly/`)와 Claude·AGY 연결 기록은 이름 기반이라 그대로 쓴다.

## 배포 패키지 (2026-10-24, 개발 확인 완료·게시 전)

- 배포 파일은 `Tokenly-<버전>-macOS-universal.zip`(최상위 `Tokenly.app` 하나, arm64·x86_64)과 `.sha256`이다. ad-hoc 서명(Identifier `io.github.jbbdyee.tokenly`), 공증 없음.
- `scripts/release.sh`로만 만든다. 배포용은 `--final <버전>`이며 깨끗한 작업 트리와 Info.plist·CHANGELOG 버전 일치가 필요하다. 같은 소스에서는 같은 ZIP이 나온다.
- 사용자는 앱을 `/Applications`로 옮긴 뒤 시스템 설정의 "그래도 열기"로 이 앱만 허용한다. Gatekeeper 비활성화는 안내하지 않는다.

## macOS 앱 목록 표시 (2026-10-24, 원인 미확정)

- 관찰: 개발자 Mac에서 같은 번들 ID의 다른 사본(임시 이름 설치, 빌드 결과물, 백업)이 해제되거나 사라진 직후 Tokenly가 앱 목록 전체 보기에서 빠졌고, 다른 앱 설치로 `/Applications`가 다시 스캔된 뒤 돌아왔다. 근거는 IMP-PLAN 51절.
- 재현(IMP-PLAN 52절): 테스트 앱에서도 같은 번들 ID의 다른 사본을 등록 해제하자 `/Applications`의 정상 설치본이 남아 있는데도 앱 목록에서 빠졌다. 중복 등록만으로는 빠지지 않았고, `/Applications` 다시 스캔만으로는 돌아오지 않았다. 앱 목록의 내부 처리 방식과 복귀 조건은 미확인이다. Tokenly 설정·서명 조건(ad-hoc, `LSUIElement`, 유틸리티)만으로 제외된다는 근거는 없다.
- 복구(IMP-PLAN 53절): 테스트 앱은 `/Applications` 경로를 `lsregister -f`로 다시 등록하자 돌아왔다. Tokenly는 2026-10-25 다시 표시되는 것을 사용자가 확인했지만, 재등록 없이 돌아왔고 시점·계기는 확인되지 않았다.
- 제품 방침: 설치·업데이트 안내에서 같은 번들 ID의 사본을 만들지 않게 하고(앱을 `/Applications`로 옮겨 한 곳에만 둠), 앱 목록에 없을 때는 Spotlight·Finder로 실행하도록 안내한다.

- **AI 주의 막대 실제 화면 검증(격리, macOS 27.0.1):** 저장소 밖 가짜 Provider의 Codex 35%·40%, Claude 30%, AGY 42%를 제품과 같은 `UsageMenuView`에 표시했다. 활성 창의 `.regularMaterial` 위에서 다크 `#F4D39A`, 라이트 `#B37914` 막대와 수치·보조 텍스트가 시각적으로 구별되고 읽혔다. 비활성 창에서는 macOS 기본 `ProgressView` tint가 회색으로 그려졌다. 이는 격리 창의 실제 화면 확인이며 설치본 팝오버·macOS 14/15·정량 픽셀 대비 검증은 아니다.
- **접근성 코드·트리 점검(수동 확인 전):** AI `UsageMenuView`의 접근성 트리에서 새로고침·설정·서비스 펼침 버튼과 Codex/Claude/AGY 한도 막대의 이름·수치가 노출됐다. 당시 자동 Tab·Space 입력으로 포커스 이동과 버튼 활성화는 확인되지 않았다. 시스템 설정은 기본 SwiftUI 스위치와 명시적 레이블을 사용한다. CPU/RAM/GPU 및 Disk의 기록 그래프는 접근성 트리에서 숨겨져 있어 시간 흐름 자체의 음성 대체 정보는 없다. 이후 사용자 수동 결과는 아래에 별도로 기록한다.
- **키보드·VoiceOver 수동 확인 준비:** 별도 번들 ID와 UserDefaults를 쓰는 Debug 사본에 실제 AI 사용량 화면과 시스템 설정 화면을 함께 띄웠다. 접근성 트리에서 다섯 스위치의 이름과 ON/OFF 상태, 세 Provider 막대 이름과 값이 확인됐고 격리 CPU 스위치 클릭 시 `off → on → off`로 바뀌었다. 자동 Tab·Space 입력은 포커스/동작 변화를 확인하지 못했다. 그래프 추세 음성 설명은 후속 개선 범위다.
- **사용자 수동 접근성 검증:** 격리 창에서 VoiceOver가 AI 서비스 이름·사용량과 시스템 설정 스위치의 이름·ON/OFF를 읽는 것을 확인했다. Control+F2로 macOS 상단 메뉴 막대에 포커스가 이동했다. Tab 여러 번으로는 Codex 버튼에 포커스가 이동하지 않았다. 키보드 탐색 설정·앱 포커스 중 어느 요인인지 확인되지 않아 일반 키보드 탐색은 원인 미확정·미검증이며 결함/정상으로 판정하지 않는다. 사용량의 정확한 퍼센트 발화 형식과 제품 설치본의 VoiceOver 동작까지 확대하지 않는다. 수동 검증은 여기서 종료한다.
- **브랜치 화면 검증 범위 확정:** CPU·배터리 변경 색은 다크·라이트 화면 밖 렌더 결과를 수용한다. 실제 앱 화면의 색과 라이트 배터리 막대 채도는 확인하지 않았으며 후속 검증으로 남긴다.
